# JDMatch 品牌视觉规范

标识、色板、尺寸与使用规则的唯一定义。视觉源文件在 Ardot 画布
`https://ardot.tencent.com/file/724373653796463`（「JDMatch 品牌视觉规范」品牌板）；
代码侧的单一数据源是 `frontend/public/logo.svg`。

## 1. 设计意图

JDMatch 做的是「简历 × JD 的匹配」，产品名本身已经含了双关：**JD 既是岗位描述，也是品牌缩写**。
标识直接把这个双关做成造型 —— 而不是另找一个与业务无关的抽象图形。

主标识是 **J 与 D 的连字**：两字共用同一条垂直主脊。

| 构造成分 | 说明 |
| --- | --- |
| 垂直主脊 | 既是 J 的笔画，也是 D 的竖杆 —— 两字共用的那条线，就是「匹配」本身 |
| D 的碗形 | 自主脊顶端向右展开一个半圆，与主脊构成完整的 D |
| J 的钩形 | 自主脊 ~64% 高度处向左回卷，底部与 D 的底边齐平，端头收圆 |
| 视觉双重含义 | 「共用一条线」在造型上就是「咬合」—— 不是拼接，而是恰好合上 |

主脊两侧的对称也经过量化：墨迹在 100×100 构造网格中占据 x 6–94、y 9–91。

## 2. 构造参数（100 × 100 网格）

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 构造网格 | 100 × 100 | 全部资产共用，等比缩放 |
| 主脊位置 | x = 53 | 垂直中线 |
| 主脊跨度 | y 16 → 84 | 上下对称，留白 16 |
| 笔画宽度 | 14（= 高度的 14%） | 同时是最小留白基准 `x` |
| 端头 | 圆端帽 + 圆角连接 | R7 |
| D 碗形半径 | 34 | 与主脊相切于 y 16 / y 84 |
| J 钩形半径 | 20 | 圆心 (33, 64)，225° 终止于 (18.86, 49.86) |
| 墨迹范围 | x 6–94，y 9–91 | 供留白与图标底板推导使用 |

绘制路径（三条，可直接复制）：

```svg
<path d="M53 16V84"                          stroke-width="14" stroke-linecap="round"/>
<path d="M53 16A34 34 0 0 1 53 84"           stroke-width="14" stroke-linecap="round"/>
<path d="M53 64A20 20 0 1 1 18.86 49.86"     stroke-width="14" stroke-linecap="round"/>
```

## 3. 标准色板

四色之外不引入新色。

| 名称 | HEX | RGB | 角色 |
| --- | --- | --- | --- |
| 墨黑 Ink | `#0A0A0B` | rgb(10, 10, 11) | 主色，占比 ~60% |
| 纸白 Paper | `#FFFFFF` | rgb(255, 255, 255) | 底色，占比 ~25% |
| 靛蓝 Indigo | `#5E6AD2` | rgb(94, 106, 210) | 强调，占比 ~10% |
| 灰 Gray | `#A1A1AA` | rgb(161, 161, 170) | 辅助，占比 ~5% |

靛蓝只用于强调位：标识中的钩形、主行动按钮、关键数值。界面大面积底色只用墨黑与纸白 ——
这与产品既有的 `.theme-xai` 纯中性墨色体系一致，标识不需要为适配主题再引入第二个色相。

## 4. 资产清单

| 文件 | 形态 | 用途 |
| --- | --- | --- |
| `frontend/public/logo.svg` | 白底墨标（墨黑 + 靛蓝钩） | 浅色背景默认形态 |
| `frontend/public/logo-white.svg` | 深底反白（纸白 + 靛蓝钩） | 深色背景形态 |
| `frontend/public/logo-mono.svg` | 单色黑 | 单色印刷、印章、传真 |
| `frontend/public/logo-mono-white.svg` | 单色白 | 深底单色场景 |
| `frontend/public/icon.png` | 512×512 应用图标 | PWA、apple-touch-icon |
| `frontend/public/favicon.ico` | 16 / 32 / 48 多尺寸 | 浏览器标签页 |
| `frontend/src/components/shared/Logo.tsx` | React 内联 SVG | 站内全部标识渲染入口 |

**不要依赖媒体查询自动翻转配色。** 早期实现用 `@media (prefers-color-scheme: dark)` 在单文件里
切换主脊颜色，但本项目的主题是 `next-themes` 基于 class 驱动的（`html.light` / `html.dark`），
两者并不等价 —— 系统深色 + 站点浅色时标识会渲染成反色而不可见。现在改为四个显式文件，
外加内联组件使用 `currentColor` 自动跟随外层文字颜色，不再有隐式行为。

### 应用图标再生成

`icon.png` 与 `favicon.ico` 由主标识推导，不手工维护：

```bash
cd frontend
pnpm generate:brand-icons
```

脚本 `frontend/scripts/generate-brand-icons.mjs` 直接读取 `public/logo.svg` 的三条路径，
因此**改标识只需改 logo.svg 再重跑脚本**，图标不会与站内标识漂移。

底板规则：圆角取边长的 22%；标识在底板内的缩放上限由「留白 ≥ x」反解得到
（留白 = 256 − 0.44·S ≥ 0.14·S ⇒ S ≤ 441），脚本取 430 留出余量。

## 5. 尺寸与最小尺寸

| 场景 | 尺寸 |
| --- | --- |
| 站内常规 | 26–60 px（组件 `size` 参数，正方形等比缩放） |
| 界面最小 | 24 px |
| 浏览器标签页最小 | 16 px |

低于 24 px 时请改用「图标版」（圆角底板 + 反白标识），避免主脊与钩形糊成一团。

## 6. 安全边距

最小留白 `x` = 主脊宽度 = 标识高度的 14%。标识四周必须保留至少 `x` 的空白，
任何文字、图形、容器边缘都不得侵入该区域。

## 7. 使用禁忌

1. 不得改变标识配色，或加入渐变、描边、投影。
2. 不得拉伸、压缩、旋转或斜切标识。
3. 不得拆散符号与字标后重新设定间距与比例。
4. 不得置于杂乱照片或无对比的底色之上。

## 8. 前端接入

```tsx
import Logo from "@/components/shared/Logo";

<Logo size={26} />                       {/* 默认：主脊跟随 currentColor，钩形用品牌强调色 */}
<Logo size={40} className="shrink-0" />  {/* className / onClick 透传到 <svg> */}
<Logo size={40} mono />                  {/* 单色：钩形与主脊同色 */}
```

组件为内联 SVG，没有额外网络请求，也不需要 `next/image` 的尺寸对齐 ——
这是修掉旧实现两处问题的关键：旧版用 `<img>` 以正方形尺寸渲染 3:2 的源图造成变形，
且配色走 `prefers-color-scheme` 与 class 主题不匹配。

导出的常量：`BRAND_ACCENT`（`#5E6AD2`）、`MARK_STEM_WIDTH`（14）、`MARK_VIEW_BOX`（100）。

### 字标

站内页头、登录页、页脚的「JDMatch」字标目前由各调用点自行用 span 渲染，
字体不统一（`font-serif` 与默认字体混用）。品牌规范建议统一为无衬线粗体、字距收紧 ——
作为后续一致性优化项，未在本次标识替换中一并改动。
